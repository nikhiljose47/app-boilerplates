When using inheritance, a child class extends a parent class and inherits its logic, which works well for hierarchical relationships like Vehicle → Car or Widget → StatelessWidget.
classes do not share actual implementation logic, forcing them into an inheritance hierarchy leads to incorrect abstraction and tightly coupled code. In such cases, 
interfaces are preferable because they allow flexibility, loose coupling, easier testing, and the ability to swap implementations without affecting higher-level code 
such as UI or controllers.
For example, different payment providers such as Razorpay, Stripe, or PayPal all support the concept of “processing a payment,” but each provider has its own SDK, API 
parameters, authentication, and request flow. An interface like PaymentService can define a method such as pay(amount), ensuring that every payment provider supports
that operation while allowing each implementation to interact with its own API internally.
